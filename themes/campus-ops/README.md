# 테마 팩: campus-ops (대학 생활)

당신은 NXT대학교 소프트웨어학부 학생회 운영진입니다. 공지를 챙기고, 동아리 모집을 관리하고, 회의록을 정리하고, 규정 문의에 답합니다 — 매주 반복되는 이 일들을 에이전트에게 맡겨 봅니다.

이 팩은 **도전 과제용**입니다. 교재 랩(NXT 스토어)을 따라하며 구조를 익힌 뒤, 같은 구조를 이 데이터로 직접 완수합니다. 절차는 알려주지 않습니다 — 무엇을 만들지(미션)와 무엇이 되면 끝인지(완수 기준)만 있습니다.

이 팩의 "오늘"은 **2026-09-14** (월)로 간주합니다.

## 도전 과제 매핑

| 도전 | 쓰는 데이터 | 미션 | 완수 기준 |
|---|---|---|---|
| 점검 크루 온보딩 | `clubs/` | 모집 요강과 지원자 명단을 대조해 문제 지원서를 걸러내는 크루를 지시문부터 직접 작성해 온보딩 | 문제 지원서 **2건**을 모두 찾아 보고받으면 완수. 1건만 찾았다면 지시문에 무엇이 빠졌는지 분석 |
| 회의록 정리 스킬 | `meetings/` | 형식 제각각인 회의록 3건을 하나의 정리 형식(결정·할 일·미정)으로 통일하는 스킬을 스스로 설계 + 규칙 1개, 인계 1개 | 새 세션에서 스킬 호출만으로 **4번째 회의록**(비품점검 메모)이 같은 형식으로 정리되면 완수 |
| 규정 Q&A 한계선 | `rules/` | 규정을 지식 소스로 등록하고, 근거 있는 질문 3개 + 규정에 없는 질문 2개를 직접 설계해 던진다 | 5개 응답을 "근거 인용 / 모름 처리 / 지어냄"으로 분류한 관찰 보고 1장. 지어냄을 발견했다면 막을 지시 1줄 제안 |
| 공지 브리핑 파이프라인 | `notices/` `schedule/` | 공지 20건을 분류·요약·정리하는 작업 명세를 직접 작성해 루프를 완주 — 통과 기준 3개 이상 포함 | 검증까지 통과하고 산출물 위치 확인. 검증에 걸린 것이 있다면 무엇이 잡혔는지가 더 좋은 보고 |
| 하루 무인 운영 | `notices/` `schedule/` | 브리핑 파이프라인에 스케줄을 걸어라 — 수집·분류는 자동, 발송은 승인 필수로 분리 | 하루 운영 후 실행 이력 캡처: 자동 실행 횟수, 승인 대기 건수, 실패 원인 한 줄 |
| 병렬 분석과 결정 | 자유 (팩 데이터 활용 권장) | 판단이 갈리는 선택지를 정의하고 분석 관점 2~3개를 병렬 위임 → 종합 자료로 결정 → 기록 | 결정 기록 제출: 선택지·근거 요약·최종 선택과 이유. 에이전트 추천과 다른 결정을 했다면 그 이유가 핵심 |

## 증분 공지 사용법 — 시간을 흐르게 하기

`notices/` 의 w3·w4·10-w1 파일은 시간 경과를 시뮬레이션합니다. 무인 운영 도전에서는 처음에 기본 파일만 두고, 실행 주기마다 증분 파일을 하나씩 폴더에 추가하십시오 — 에이전트 입장에서 "새로 게시된 공지"가 됩니다. 정정 공지, 일정 연장, 부서 간 유사 공지가 섞여 들어오므로 브리핑이 매번 같을 수 없습니다.

## 재도전·변형: 축제 부스 신청 심사

점검 크루 도전을 다시 하고 싶다면 `festival/booth-guidelines.md` 와 `booth-applications.md` 로 같은 구조를 다른 데이터에서 반복할 수 있습니다 — 기준 문서가 다르고, 걸리는 지점도 다릅니다. 그리고 `festival/` 의 작년 기록·예산·인력 자료는 병렬 분석·결정 도전에서 "부스 형태(학부 단독 vs 동아리 연합)" 판단의 실제 재료가 됩니다 — 이 안건이 왜 미결인지는 회의록에 이력이 있습니다.
