# made-to-report

기초전자회로실험(및 유사 실험) 보고서를 **정해진 구성과 원칙**에 따라 작성하기
위한 지침 스킬. 아래 지침을 반드시 지켜 예비 보고서와 결과 보고서를 작성한다.

## When to use

- "이번 실험 보고서 작성해줘 / 결과보고서 만들어줘"
- 측정 데이터(전압·전류·저항 등)와 실험 방법이 있고, 이론값과 비교·오차 분석이
  필요한 보고서를 정리해야 할 때.
- 예비 보고서(목적·장비·이론·방법)만, 또는 결과 보고서(결과·검토·의견)만
  작성할 때도 해당 파트의 원칙을 그대로 따른다.

## 입력 / 출력

- **입력**: 실험 주제·목적, 실험 장비/방법, 측정 데이터(표 또는 CSV), 필요 시
  측정 사진, 관련 자료.
- **출력**: 아래 구성을 따르는 보고서 문서(HTML / Markdown / docx 등 요청 형식).
  본 세션에서 생성하는 파일·산출물은 `my-work/` 폴더에 저장한다.

## 작성 절차

1. 실험 주제와 제공된 데이터·자료를 확인한다. 측정값·계산값·이론값을 명확히
   구분해 둔다.
2. **예비 보고서** 4개 항목을 작성한다: 실험 목적/주제 → 실험 장비 → 기초 이론
   → 실험 방법.
3. **결과 보고서** 3개 항목을 작성한다: 실험 결과 → 결과에 대한 검토 → 결과에
   대한 의견. 이어서 결론을 정리한다.
4. 아래 6개 원칙을 모든 항목에 적용한다(구성·결과·검토·의견·결론·스타일).
5. 확인되지 않은 값은 만들어내지 않는다. 불명확하면 사용자에게 확인한다.

---

## 지침: 기초전자회로실험 보고서 작성 지침

실험 보고서를 작성할 때 다음 원칙을 반드시 따른다.

## 1. 보고서 기본 구성

보고서는 다음과 같은 구조를 기본으로 한다.

### [예비 보고서]

1. 실험 목적 또는 실험 주제
2. 실험 장비
3. 기초 이론
4. 실험 방법

### [결과 보고서]

1. 실험 결과
2. 결과에 대한 검토
3. 결과에 대한 의견

---

## 2. 실험 결과 작성 원칙

실험 결과에서는 실제 측정된 데이터를 중심으로 작성한다.

* 측정한 전압, 전류, 저항 등의 실험 데이터를 빠짐없이 기록한다.
* 측정 결과는 필요한 경우 사진과 함께 제시한다.
* 측정 데이터는 표를 활용하여 보기 쉽게 정리한다.
* 측정값을 바탕으로 필요한 계산값을 구한다.
* 각 측정 데이터에 대해 이론값을 계산하고 측정값과 비교한다.
* 측정값과 이론값 사이의 오차를 계산하고 그 원인을 분석한다.
* 단순히 데이터를 나열하지 말고, 데이터에서 나타나는 특징과 결과의 의미를 설명한다.

---

## 3. 결과에 대한 검토

결과에 대한 검토에서는 실험 결과를 분석하고 오차의 원인을 논리적으로 설명한다.

### 결과 분석

* 측정값과 이론값이 일치하는지 또는 차이가 있는지 확인한다.
* 데이터 간에 나타나는 특징이나 차이를 설명한다.
* 특정 데이터에서 예상과 다른 결과가 나타났다면 그 이유를 분석한다.

### 오차 원인

오차가 발생한 경우 다음과 같은 가능성을 고려하여 구체적으로 분석한다.

* 측정 기기의 한계 및 오차
* 실험 환경의 변화
* 회로 및 부품의 특성 차이
* 접촉 저항
* 측정 과정에서 발생할 수 있는 오차
* 기타 실험 조건에 따른 오차

단순히 "실험 오차 때문에 발생했다"고 작성하지 말고, 어떤 요인이 어떤 방식으로 측정 결과에 영향을 주었는지 설명한다.

### 데이터의 일관성

* 측정 데이터가 전체적으로 일정한 경향을 보이는지 확인한다.
* 특정 상황에서 데이터가 일관되지 않다면 해당 부분을 지적하고 추가적인 검토가 필요한 이유를 설명한다.

---

## 4. 결과에 대한 의견 작성 원칙

결과에 대한 의견은 **일기장이나 감상문처럼 작성하지 않는다.**

다음 내용을 중심으로 객관적이고 기술적으로 작성한다.

* 실험에서 확인한 이론과 실제 측정 결과의 비교
* 실험 결과를 통해 판단할 수 있는 실험의 신뢰성
* 발생한 오차 또는 문제점
* 실험 결과를 개선하기 위한 구체적인 개선 방안
* 실험을 통해 확인한 핵심적인 결론

특히 **개선 방안을 반드시 포함한다.**

---

## 5. 결론 작성 원칙

결론은 실험에서 무엇을 수행했고, 어떤 결과를 얻었으며, 이론과 어떤 관계가 있었는지를 간결하게 정리한다.

기본적인 작성 흐름은 다음과 같다.

**실험 내용 -> 측정 결과 -> 이론값과의 비교 -> 차이가 발생한 원인 -> 개선 방안 및 결론**

예시적인 문장 구조:

"본 실험에서는 ~~ 회로에 대한 실험을 ~~ 방식으로 진행하였다. 결론적으로 ~~ 값이 측정되었으며 이론값과 ~~한 차이가 나타났다. 이러한 차이가 발생한 이유는 ~~으로 예상된다. ~~을 개선한다면 이론값에 더욱 가까운 결과를 얻을 수 있을 것으로 판단된다."

실험 주제에 따라 다음과 같은 방식으로 확장할 수도 있다.

"본 실험에서는 ~~에 대해 알아보는 실험을 ~~ 방식으로 진행하였다. ~~는 ~~한 특징을 가지고 있으며 ~~하다. 이러한 특성을 이용하면 ~~가 가능하며, 실제 산업에서는 ~~의 목적으로 사용된다. ~~을 개선한다면 새로운 방식으로 산업에 적용할 수 있을 것으로 판단된다."

---

## 6. 작성 스타일

* 보고서는 객관적이고 기술적인 문체로 작성한다.
* 개인적인 감상이나 단순한 소감을 중심으로 작성하지 않는다.
* 실험에서 실제로 확인한 사실과 분석을 구분한다.
* 측정값, 계산값, 이론값을 명확하게 구분한다.
* 결과를 설명할 때 가능한 경우 수치와 근거를 함께 제시한다.
* 오차가 있다면 단순히 존재한다고 언급하지 말고 원인을 분석한다.
* 결과에 문제가 있더라도 임의로 데이터를 수정하거나 실제 측정하지 않은 값을 만들어내지 않는다.
* 제공된 실험 데이터와 자료를 우선적으로 활용하며, 확인되지 않은 내용을 사실처럼 작성하지 않는다.
* 보고서의 내용은 실험 목적과 결과가 자연스럽게 연결되도록 작성한다.
* 결론에서는 단순히 실험 내용을 반복하지 말고, 실험을 통해 확인한 핵심 결과와 의미를 정리한다.

---

## 주의사항

- 측정하지 않은 값·확인되지 않은 내용을 사실처럼 만들어내지 않는다.
- 측정값 / 계산값 / 이론값을 항상 구분해 표기한다.
- 오차는 존재 여부만 언급하지 말고 원인을 구체적으로 분석한다.
- 의견·결론에는 **개선 방안**을 반드시 포함한다.
- 이 세션의 산출물 파일은 `my-work/` 폴더에 저장한다.

## 참고자료(출처) 처리

- 보고서 끝에 **참고자료** 섹션을 두고, 방대하지 않게 **2~3줄**로 유지한다.
- 매주 주제가 바뀌므로, 출처는 **그 주제에 맞게 Kiro가 채운다**. 사용자가 직접
  찾지 않아도 된다.
- 채울 때는 해당 실험 주제의 **표준 교재·강의자료·널리 알려진 참고문헌**만
  넣는다. 존재가 확실하지 않은 자료(가짜 논문·지어낸 URL·불확실한 저자/연도)는
  넣지 않는다. 확실하지 않으면 일반적 교재/강의자료 수준으로만 기재한다.
- 형식은 간단히: 저자/기관, 제목, (판·연도) 정도. 과한 서지 정보는 지양.
