# 국민대 AI플랫폼개발 W02 실습 안내

10명 각자 실행하고, 마지막에 2명씩 5쌍으로 결과를 비교합니다.

## 준비 순서 · 첫 Push 후 Crew 연결

1. Kiro IDE 설치·로그인 → Node.js·npm 확인 → Kiro CLI 인증 → Crew 설치·진단.
2. Git·GitHub CLI 설치 확인 → `gh auth login`으로 HTTPS·브라우저 인증 → `gh auth status`.
3. nxtcloud-edu 수업 레포를 내 계정에 Public Fork → 내 포크를 Clone → Kiro IDE에서 로컬 레포 열기.
4. `upstream`은 nxtcloud-edu 원본, `origin`은 내 포크인지 확인. 커밋 작성자 이름·이메일 설정.
5. `class/kookmin-2026-2/ai-platform-development/week02/submissions/start.md`를 IDE에서 만들고 저장.

```markdown
# 나의 첫 작업 기록
AI로 줄이고 싶은 일: (내 관심사)
이번 수업에서 확인할 것: (내 질문)
```

레포 루트에서 IDE 터미널 실행:
```sh
cd class/kookmin-2026-2/ai-platform-development/week02
git status
git add submissions/start.md
git commit -m "docs: 첫 작업 기록"
git push origin main
```

6. 내 GitHub 포크를 새로고침해 `start.md` 내용과 커밋 메시지를 확인. 첫 Push 성공을 확인한 뒤 다음 단계 진행.
7. Kiro Crew에서 **방금 Clone한 동일한 로컬 레포의 최상위 폴더**를 프로젝트로 열기. GitHub URL이나 submissions 폴더를 선택하는 것이 아님.
8. 첫 크루 생성 → 프로젝트 연결 확인 → 수업 자료 읽기와 첫 업무 지시.

`start.md`는 학생이 직접 작성하는 첫 기록입니다. 강사 원본에는 완성 파일을 배포하지 않습니다. 이후 AI 실습 결과와 컨텍스트 파일도 같은 submissions 아래에 누적합니다.

설치 상세는 [SETUP.md](../../../../SETUP.md), Fork·Clone·인증 상세는 [GitHub 제출 안내](01_GitHub_준비와_제출.md)를 참고합니다.

## 2. 첫 크루

- 이름: `campus-helper`
- TRIGGERS: `수업 공지, 과제 점검, 진로 준비`
- 템플릿 `kirocrew`, 새 Workspace, Memory store `default`
- 세션 프로젝트는 저장소 최상위 폴더. 새 세션에서도 연결을 확인합니다.

## 3. 함께 실습 · 수업 공지·과제 관리

가상 자료의 기준 시각은 **2026-09-09 09:00 KST**입니다. 현재 날짜를 대신 사용하지 않습니다.
먼저 두 파일을 읽고 바뀐 마감과 확인이 필요한 내용을 예상합니다.

```text
기준 폴더: class/kookmin-2026-2/ai-platform-development/week02/
이 폴더의 data/course/notices.md와 data/course/my-tasks.md를 읽어 줘.
자료 기준 시각으로 과제별 마감·제출 조건·현재 준비 상태를 대조해 줘.
이번 주 할 일과 확인 필요한 항목을 공지 ID 근거와 함께 보고해 줘.
확인할 수 없는 것은 추측하지 말고, 아직 파일은 만들지 마.
```

원문과 첫 보고를 대조한 뒤 기준을 보완합니다.

```text
같은 과제의 변경 공지는 무엇을 바꿨는지 확인해서 적용해 줘.
날짜만 있는 마감에 시각을 만들어 넣지 마.
준비 완료와 실제 제출 완료를 구분해 줘.
각 항목의 근거와 사람에게 확인할 질문을 적어 줘.
```

검증 후 저장:

```text
기준 폴더: class/kookmin-2026-2/ai-platform-development/week02/
검증 결과를 submissions/course-check.md에 저장해 줘.
과제·마감·할 일·근거·확인 질문 순서로 정리해 줘.
입력 원본은 수정하지 말고 실제 제출·일정 등록도 하지 마.
같은 결과 파일이 있으면 덮어쓰지 말고 알려줘.
```

## 4. 내 작업 기록 → 새 자료 반영 → 새 세션 재개

이어서 [작업 이어가기](05_작업_이어가기.md)를 순서대로 진행합니다. 첫 작업 Commit·Push 후 강사가 새 공지를 배포하면 포크 동기화·Pull을 수행합니다. 기존 계획만 필요한 만큼 갱신하고, 판단 기준과 작업 상태를 파일로 남겨 새 세션에서 재개합니다.

## 5. 선택 확장 · 인턴·채용 공고

기본 흐름을 마친 학생은 data/career/job-postings.md와 my-profile.md로 지원 준비를 점검합니다. 필수·우대, 미기재·미충족, 정정 공지를 구분합니다. 최초 결과와 검증 결과는 career-first.md, career-check.md로 보관합니다. 실제 지원·연락은 하지 않습니다.

## 제출

[개인 제출 폴더](submissions/README.md)의 필수 결과와 실행 기록을 자신의 포크에 Commit·Push합니다. [GitHub 안내](01_GitHub_준비와_제출.md)를 참고하고 URL·최종 커밋 링크를 제출합니다. 다음 주에는 기록한 기준과 반복 절차를 Skill로 연결합니다.

## 원리 이해와 다른 업무 적용
[실습의 핵심과 전이](06_내_업무에_적용.md)를 따라 자신의 업무를 정하고 submissions/transfer-plan.md에 설계합니다. 명령 실행뿐 아니라 맡길 범위·검증 기준·기록 이유를 설명합니다.

## 직접 수행과 확인 지점

1. 첫 보고 후 바로 정답 화면으로 넘어가지 않고, 공지 ID 한 건을 원문과 대조합니다. 검증한 근거 또는 확인이 필요한 항목을 `submissions/execution-record.md`에 적습니다.
2. 자기 기준 하나를 보완해 다시 실행하고, 바뀐 결과와 이유를 같은 실행 기록에 추가합니다. 오류가 없다면 맞다고 판단한 근거를 설명합니다.
3. 새 공지를 받은 뒤에는 바꿀 파일과 보존할 파일을 먼저 정합니다. 계획의 변경 줄과 개인 메모 보존 여부를 확인합니다.
4. 기준·상태 파일을 새 세션에서 읽히고 완료·미해결·다음 행동을 원문과 대조합니다. 짝과 빠진 맥락을 비교하고 파일에 보완합니다.
5. 처음 `start.md`에 적은 자기 일을 돌아보고 `submissions/transfer-plan.md`에 입력·원하는 결과·도구·수정 경계·성공 기준을 정리합니다.

새로운 과제 파일을 늘리기보다 기존 실행 기록과 컨텍스트 파일에 판단 근거를 누적합니다.
