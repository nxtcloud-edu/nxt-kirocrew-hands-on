# 05 · 변경하고, 기록하고, 이어가기

경로는 `week02/` 기준. Git 명령은 **저장소 최상위 폴더**에서 실행.

## 1. work.md 두 항목 확인

[03 첫 업무](03_실습_안내.md)에서 작성한 파일을 Kiro IDE로 엽니다.

- **할 일**: AI가 정리한 과제별 마감·다음 행동
- **내 일정·조건**: 내가 직접 적은 조건 한두 줄

이미 작성했다면 다시 만들지 않습니다. 다음 단계에서는 할 일만 갱신하고 내 조건은 보존합니다.

## 2. 기준점 Commit·Push

```sh
git status
git add class/kookmin-2026-2/ai-platform-development/week02/submissions/
git diff --cached
git commit -m "2주차 첫 작업과 개인 메모 기록"
git push origin main
```

자기 GitHub에서 파일 내용과 커밋 확인.

## 3. 새 공지 Pull

강사의 배포 안내 후, 내 작업을 먼저 Commit합니다. `main` 브랜치에서 **upstream → local → origin** 순서로 반영합니다.

```sh
git switch main
git pull --no-rebase upstream main
git push origin main
```

`data/course/updates-01.md` 확인. 배포 전에는 없는 파일.
Pull은 원본 변경을 내 작업과 합치고, Push는 자기 포크에 반영합니다. 충돌이 나면 해결 전 Push하지 않습니다.
충돌·분기 오류는 강사와 확인. 강제 Push·Discard commits 금지.

## 4. 기존 계획 갱신

```text
기준 폴더: class/kookmin-2026-2/ai-platform-development/week02/
data/course의 초기 자료와 updates-01.md, submissions/work.md를 읽어 줘.
새 공지로 바뀔 항목과 수정 계획을 먼저 보여줘.
승인 후 work.md의 "할 일"에서 영향받는 항목만 수정해 줘.
"내 일정·조건"과 입력 원본은 보존해 줘.
변경 이유는 대화에서 설명해 줘.
```

승인·실행 후 IDE와 `git diff`로 **변경 범위·내 일정·조건 보존·원문 근거** 확인.

## 5. 기준·상태 기록 → 다시 Push

**이제 처음으로** `submissions/context.md`를 엽니다. 새 세션에 넘길 내용을 제목별로 작성:

- 판단 기준: 적용할 기준 + 이유
- 현재 상태: 완료·미해결
- 다음 행동: 할 일·읽을 경로·수정 및 보존 범위

빈 양식을 채우고 이미 쓴 내용은 보존. AI 제안은 직접 검토.
2단계 명령을 반복하되 메시지는 `2주차 변경 공지 반영과 판단 기준 기록`.

## 6. 새 세션에서 재개

같은 크루의 새 세션에 같은 프로젝트 연결. 이전 대화는 붙여넣지 않기.

```text
기준 폴더: class/kookmin-2026-2/ai-platform-development/week02/
submissions/context.md와 참조 자료를 읽어 줘.
지킬 기준·완료·미해결·다음 행동을 정리해 줘.
work.md의 "할 일"을 점검하고, 수정 전 계획을 보여줘.
```

실제 기록과 대조 → 빠진 맥락 보완 → 짝과 판단 기준 비교.
[내 업무 적용](06_내_업무에_적용.md)은 짝과 말로 설명합니다. 최종 수정 사항은 Commit·Push.
