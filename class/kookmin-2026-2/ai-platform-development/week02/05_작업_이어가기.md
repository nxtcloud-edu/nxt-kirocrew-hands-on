# 작업을 기록하고 이어가기
## 저장소 이름 · upstream / origin / local
- upstream: nxtcloud-edu의 수업 원본을 가리키도록 등록하는 remote 이름.
- origin: 자기 GitHub 포크를 Clone할 때 자동 등록되는 remote 이름.
- local: 내 컴퓨터의 저장소. remote 이름이 아닙니다.

Clone 후 저장소 안에서 `git remote -v`를 확인하고 upstream이 없을 때만 한 번 실행합니다. 아래는 모든 셸에서 복사할 수 있는 한 줄 명령입니다.
```sh
git remote add upstream https://github.com/nxtcloud-edu/nxt-kirocrew-hands-on.git
git remote -v
```
upstream이 이미 있으면 URL을 확인하며, 임의로 덮어쓰지 않습니다. origin은 자기 계정, upstream은 nxtcloud-edu 주소인지 확인합니다.
갱신은 **GitHub Sync fork: upstream 원본 → origin 포크**, 이후 **git pull --ff-only origin main: origin → local**입니다. 결과는 local에서 Commit한 뒤 origin에 Push합니다. upstream에 Push하지 않습니다. remote 이름은 관례이며 자동 권한·자동 동기화를 뜻하지 않습니다.


이번 실습은 웹 채팅에서 보고서를 받는 경험을 넘어, AI가 로컬 파일을 읽고 기존 작업을 수정하며 다음 세션까지 이어가는 경험입니다.
모든 경로는 `class/kookmin-2026-2/ai-platform-development/week02/` 기준입니다. 10명 각자 수행합니다.

## 1. 첫 작업과 내 메모
기존 실습 안내의 과제 점검을 먼저 진행합니다. 첫 결과는 `submissions/course-first.md`, 검증한 결과는 `submissions/course-check.md`에 보관합니다.
검증한 보고를 바탕으로 AI에게 `submissions/workspace/task-plan.md`에 과제별 준비 체크리스트를 만들게 합니다. 공지 ID, 마감, 다음 행동, 확인 질문을 포함합니다.
학생은 `submissions/workspace/my-notes.md`를 직접 만들고 자신의 계획 두 줄을 씁니다. 예: “수요일 저녁에는 동아리 일정”, “CSV는 목요일 오전에 확인”. 이것은 가상 연습 계획이며 이후 AI가 임의로 바꾸면 안 됩니다.

## 2. 첫 기준점 · Commit과 Push
저장소 최상위 폴더의 IDE 터미널에서 실행합니다.
```sh
git status
git add class/kookmin-2026-2/ai-platform-development/week02/submissions/
git diff --cached --stat
git commit -m "2주차 첫 작업과 개인 메모 기록"
git push origin main
```
선택된 파일을 확인한 후 커밋합니다. `origin`은 자신의 포크입니다. 브라우저에서 파일과 커밋이 보이는지 확인하고 커밋 링크를 실행 기록에 남깁니다.

## 3. 강사의 새 공지 받기
강사의 배포 안내가 있을 때만 진행합니다. 본인 작업을 먼저 Commit·Push한 뒤 GitHub 자신의 포크에서 **Sync fork → Update branch**를 실행합니다.
저장소 최상위 폴더에서:
```sh
git status
git pull --ff-only origin main
```
`data/course/updates-01.md`가 생겼는지 확인합니다. 아직 없다면 배포 여부를 강사에게 확인합니다. 충돌·분기 오류가 나면 강제 Push나 Discard commits를 사용하지 말고 강사와 확인합니다. nxtcloud-edu 원본에 PR을 보내지 않습니다.

## 4. 기존 작업 갱신
```text
기준 폴더: class/kookmin-2026-2/ai-platform-development/week02/
data/course의 초기 자료와 updates-01.md, submissions/course-check.md,
submissions/workspace의 계획과 개인 메모를 읽어 줘.
새 공지 때문에 바뀌어야 하는 항목과 수정 계획을 먼저 알려줘.
승인 후 task-plan.md의 영향받는 항목만 수정해 줘.
my-notes.md와 입력 원본, 첫 보고는 수정하지 마.
변경 근거와 남은 확인 사항을 보고해 줘.
```
수정 계획을 확인하고 승인합니다. `git diff -- class/kookmin-2026-2/ai-platform-development/week02/submissions/`로 변경을 확인합니다. 새 파일은 아직 diff에 나오지 않을 수 있으므로 IDE에서 직접 열고 `git status`도 확인합니다.
개인 메모 보존, 변경 공지의 적용 범위, 미기재 시각 추측 여부를 점검합니다.

## 5. 내 판단을 파일로 남기기
`양식/판단_기준.md` → `submissions/context/decision-rules.md`, `양식/작업_상태.md` → `submissions/context/work-state.md`로 복사합니다.
AI가 제안한 규칙을 사람이 검토하고 자기 말로 수정합니다. 단순 대화 복사가 아니라 **다음 작업에도 적용할 기준과 이유**를 남깁니다.
예: “날짜만 있으면 임의의 시각을 추가하지 않음 — 공지에 없는 사실을 만들지 않기 위해”.
작업 상태에는 완료한 일, 확인하지 못한 일, 다음 행동, 읽을 파일 경로를 기록합니다.

## 6. 변경 후 Commit과 Push
1단계 명령과 같은 범위를 사용하되 커밋 메시지는 `2주차 변경 공지 반영과 판단 기준 기록`으로 씁니다. 첫 기준점과 이번 커밋을 비교합니다.
Git은 변경을 기록하고, 기준 파일은 이유를 남기며, 상태 파일은 다음 행동을 연결합니다. 커밋 자체가 AI의 자동 기억은 아닙니다.

## 7. 새 세션에서 이어가기
같은 크루의 새 세션을 열고 수업 프로젝트를 연결합니다. 앞 대화를 붙여넣지 않습니다.
```text
기준 폴더: class/kookmin-2026-2/ai-platform-development/week02/
submissions/context의 두 파일과 거기서 참조한 자료를 읽어 줘.
지킬 기준, 완료한 작업, 미해결 사항, 다음 행동을 정리해 줘.
기준에 따라 task-plan.md에서 아직 확인이 필요한 항목을 점검해 줘.
파일 수정 전 계획을 먼저 보여줘.
```
학생은 실제 기록과 대조해 재개가 가능한지 확인합니다. 누락된 맥락이 있으면 상태 파일을 보완하고 이유를 기록합니다. 작업 파일의 변경 이력은 남기되, 새 세션이 과거 대화를 전혀 모른다고 단정하지 않습니다. 파일로 필요한 맥락이 전달되는지를 검증합니다.

## 8. 짝 비교와 제출
서로 다른 판단 기준 하나, 보존한 메모, 새 세션에서 빠진 맥락을 비교합니다. 모든 결과는 자기 포크의 submissions에 저장합니다.
최종 보완 내용도 Commit·Push하고 URL과 커밋 링크를 제출합니다. `execution-record.md`에 첫 기준점·갱신·재개 후 커밋 링크와 검증 결과를 남깁니다. 링크 기록 자체가 포함될 마지막 커밋은 GitHub 제출 링크로 별도 전달하면 됩니다.
채용 공고 점검은 빠르게 마친 학생의 확장 도전입니다. 같은 방식으로 준비 계획·판단 기준을 만들어 봅니다. 공통 필수 제출에 career 파일은 포함하지 않습니다.
