# 실습에서 가져갈 원리

## 수업의 목표
도구의 버튼과 명령을 외우는 것보다, 자신의 일을 AI와 수행할 수 있는 구조로 정의하고 다른 업무에도 적용합니다. 과제 점검은 이 구조를 연습할 사례입니다.

| 원리 | 이번 실습에서 확인할 것 | 내 업무로 옮길 질문 |
|---|---|---|
| 맡길 일 판단 | 단순 날짜 정렬과 자연어 변경 해석 구분 | 규칙·필터로 충분한가, 해석이 필요한가? |
| 결과와 단계 구체화 | 보고 → 검증 → 계획 파일 → 변경 반영 | 완료된 결과의 형태와 필요한 중간 단계는? |
| 근거·컨텍스트 선택 | 공지·개인 기록·변경 공지 함께 읽기 | 어떤 자료가 최신이며 무엇을 근거로 판단할까? |
| 실행 경계 설정 | data 보존, 계획 수정, 개인 메모 보존 | 바꿔도 되는 것과 사람에게 물어야 할 것은? |
| 검증 기준 정의 | 마감·제출 조건·변경 범위·메모 확인 | 맞고 틀림을 무엇으로 확인할까? |
| 판단을 명시 | 발견한 오류에서 규칙과 이유 기록 | 내가 당연하게 생각해 말하지 않은 조건은? |
| 작업을 이어가기 | Git 이력 + 기준 파일 + 상태 파일 | 새 세션이나 다른 사람이 다음 행동을 알까? |

## 강사의 진행 원칙
- 설명은 “무엇을 누르는가 → 왜 필요한가 → 내 일에서는 무엇인가”로 연결합니다.
- 성공 화면을 따라 얻는 것보다 학생이 선택한 기준과 수정 이유를 묻습니다.
- 오류는 모든 학생에게 동일하게 나타난다고 가정하지 않습니다. 오류가 없으면 결과의 근거와 보존 조건을 설명하게 합니다.
- 명령 실행 속도와 모델의 성능을 학생 이해도로 혼동하지 않습니다.
- 추가 평가비율을 만드는 문서가 아닙니다. 아래 질문은 수업 중 이해 확인용입니다.

## 왜 지금 내부 과정을 배우는가 · 강의자 메시지
[강의자 관점 · 왜 지금 배우는가]
앞으로 AI 성능이 더 좋아지고 도구들이 발전하면, 오늘 우리가 하나씩 하는 일을 제품이 뒤에서 처리해 줄 가능성이 큽니다. 파일을 찾고, 도구를 고르고, 작업 상태를 정리하고, 다음 실행으로 넘기는 과정이 버튼 하나 뒤로 들어가는 것이죠. 이런 것을 추상화한다고 합니다. 복잡한 내부 과정을 일일이 알지 않아도 쓸 수 있도록 감싸 주는 겁니다.
그렇다면 곧 안 보이게 될 것을 왜 지금 배우느냐고 물을 수 있습니다. 바로 지금은 그 안에서 무슨 일이 일어나는지 직접 보고 이해하기 좋은 시기이기 때문입니다. 저는 이 중간 과정을 볼 수 있는 기회가 귀하다고 생각합니다. 앞으로 영원히 볼 수 없다는 기술적 단정이 아니라, 제품을 사용하는 일상에서는 점점 덜 보게 될 것이라는 제 관점입니다.
요즘은 스마트폰으로 사진을 잘 찍을 수 있죠. 그렇다고 빛과 노출을 이해한 사람이 가진 판단력이 사라지는 것은 아닙니다. 자동으로 잘되는 상황에서는 차이가 작을 수 있어도, 원하는 결과가 안 나오거나 낯선 상황을 만나면 무엇을 바꿔야 할지 생각할 근거가 있습니다. AI도 비슷합니다. 완성된 도구를 쓰는 것 자체가 잘못은 아닙니다. 우리는 그 도구를 평가하고 내 일에 맞게 바꿔 적용할 수 있는 이해까지 갖추려는 겁니다.
오늘 외울 것은 이 버튼의 위치나 특정 명령어가 아닙니다. 무엇을 읽고, 무엇을 근거로 판단하고, 어디를 바꾸며, 어떻게 확인하고, 다음 작업에 무엇을 넘기는지입니다. 도구는 바뀌어도 이 질문은 다른 업무에서 다시 쓸 수 있습니다.
