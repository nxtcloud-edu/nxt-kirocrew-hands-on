# 국민대 AI플랫폼개발 W02 실습 안내

10명 각자 실행하고, 마지막에 2명씩 5쌍으로 결과를 비교합니다.

## 1. 설치와 자료

- [Kiro 공식 다운로드](https://kiro.dev/downloads/): Kiro IDE를 설치하고 수업 안내 계정으로 로그인합니다.
- [실습 자료 저장소](https://github.com/nxtcloud-edu/nxt-kirocrew-hands-on): Code → Download ZIP으로 받은 뒤 압축을 풉니다. Git이 설치되어 있다면 clone해도 됩니다.
- IDE에서 `SETUP.md`가 있는 최상위 폴더를 엽니다.
- [기본 교재](https://workshop.nxtcloud.kr/courses/kiro-crew/00-overview)의 Lab 00과 Lab 01에서 세부 화면을 확인합니다.

IDE 채팅에 입력:

```text
이 폴더의 SETUP.md를 읽고 "0. 사전 요구 점검과 설치"와
"2. Kiro Crew 설치"를 순서대로 진행해 줘.
kiro-cli login과 kirocrew setup은 실행하지 마. 그 단계는 내가 직접 할게.
완료 보고와 kirocrew --version 결과를 보여 줘.
```

실행할 명령을 확인하고 승인합니다. 로그인과 초기 설정은 직접 진행합니다. 이미 올바르게 로그인했다면 재인증할 필요는 없습니다.

```bash
kiro-cli login
kiro-cli whoami
kirocrew --version
kirocrew setup
```

초기 설정: Workspace 기본값, 한국 시간대 `Asia/Seoul`, Slack 연동 `n`, 데스크톱 앱 설치 `n`, AWS 실행은 기본 아니오. 실제 질문을 읽고 답합니다.

```bash
kirocrew doctor
kirocrew gateway
```

[내 대시보드](http://localhost:5476)를 엽니다. Gateway 터미널은 유지합니다. 처음 Import Setup이 나오면 Skip all을 선택합니다. Normal 승인 모드로 수업 폴더를 연결합니다. ZIP 자료는 Git 브랜치 표시가 없어도 됩니다.

명령이 인식되지 않으면 새 터미널에서 확인합니다. Windows 소스 설치의 경우 `SETUP.md`에 안내된 가상환경 활성화도 확인합니다. 막힌 명령과 오류 문구를 강사에게 보여주세요.

설치는 저장소 최상위 폴더에서 진행합니다. 이번 수업 입력은 `class/kookmin-2026-2/week02/data/`, 결과 저장은 `class/kookmin-2026-2/week02/results/`를 사용합니다. 교재 캡처의 `labs/` 경로 대신 이 안내의 경로를 사용하세요.

## 2. 첫 크루

- 이름: `nxt-store-ops`
- TRIGGERS: `주문 점검, 재고 점검, 운영 보고`
- 템플릿: `kirocrew`
- Workspace: 새 작업 공간 생성
- Memory store: `default`

세션에서 크루를 선택한 뒤 프로젝트를 다시 확인합니다. `SETUP.md`와 `class/`가 있는 저장소 최상위 폴더여야 합니다.

## 3. 첫 업무

원문 두 개를 먼저 읽고 문제를 예측합니다. 이후 아래 지시를 입력합니다.

```text
class/kookmin-2026-2/week02/data/store/orders-today.md와
class/kookmin-2026-2/week02/data/store/inventory-status.md를 읽고,
주문을 재고와 대조해서 문제가 있는 주문을 보고해 줘.
확실하지 않은 것은 추측하지 말고 확인 불가로 표시해. 파일은 만들지 마.
```

결과의 주문번호·품목·수량·근거를 원문과 대조합니다. 필요한 경우 판단 기준을 보완합니다.

```text
같은 고객이 같은 품목을 여러 번 주문한 경우도 확인 대상으로 표시해 줘.
중복 실수라고 단정하거나 주문을 취소하지 마.
각 항목에 근거와 다음 확인 사항을 적어 줘.
```

검증한 결과를 저장합니다.

```text
검증한 결과를 class/kookmin-2026-2/week02/results/daily-check.md에 저장해 줘.
문제 주문, 확인할 항목, 정상 주문 순서로 근거를 적어.
입력 원본은 수정하지 마.
같은 이름의 파일이 있으면 덮어쓰지 말고 알려줘.
```

승인 전에 경로와 변경 내용을 확인합니다. 저장 후 실제 파일을 열어봅니다.

## 4. 직접 도전: 동아리 지원서 점검

가상 NXT대학교 자료이며, 자료 속 기준일은 **2026-09-14**입니다.

입력 파일:

```text
class/kookmin-2026-2/week02/data/clubs/recruit-notice.md
class/kookmin-2026-2/week02/data/clubs/applicants.md
```

**미션:** 모집 요강과 접수 명단을 대조해 운영진이 확인할 지원서를 보고하세요. 접수번호·근거·다음 확인 사항을 포함하세요. 자료에 없는 사실은 추정하지 말고, 최종 선발·삭제·연락은 수행하지 않습니다.

완성 프롬프트는 제공하지 않습니다. 입력·판단 기준·출력·사람에게 확인할 지점을 직접 설계합니다.

진행 순서(수업 상황에 따라 조정):

1. 원문 읽기·판단 기준 작성
2. 내 지시문으로 첫 실행
3. 결과와 원문 대조, 누락·추정 표시
4. 기준 보완·재실행·최종 보고 검증
5. 짝과 다른 판단 및 근거 비교

최종 보고서는 `class/kookmin-2026-2/week02/results/club-check.md`에 저장합니다. 원본은 수정하지 않고 기존 결과 파일도 덮어쓰지 않습니다.

[실행 기록 양식](실행_기록_양식.md)을 `class/kookmin-2026-2/week02/results/execution-record.md`에 복사해 작성합니다.

